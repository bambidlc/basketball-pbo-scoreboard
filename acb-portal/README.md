# Portal de Inscripción ACB 2027 + sitio web ACB (Odoo)

Two pieces that share one brand layer (`shared/brand.css`, `shared/hero.js`) and one
set of tournament rules (`shared/tournament.js`, `shared/validation.js`):

1. **Registration portal** (this folder, deployed as its own Render web service).
   Everything starts at **`/mi-club`**: a club searches the clubs already in the portal and
   sees its status (email confirmed, missing profile fields, teams sent/approved, ACB
   review). If it is there, it enters with the club's access email (plus a one-time
   emailed code when `LOGIN_CODE_REQUIRED=1`) and goes on to complete what is missing; if not, it requests the club in the same page (club,
   board, court, insurance and access email). Old `/registro` and `/entrar` links
   redirect there. Inside the portal the club completes every team: staff with
   federation cards, uniform colors, up to 13 players with sizes, school, grade,
   guardian e-signature, birth certificate and photo. It validates eligibility and the
   2-team coach rule, computes fees, and prints the Hoja de Uniformes, Lista Oficial,
   Carnet and Roster (×3). Data lives in Odoo in the `x_acb_club`, `x_acb_team` and
   `x_acb_player` models (menu **ACB Inscripciones**).
2. **ACB website** on Odoo website #2 ("ACB"), generated by `odoo-website/build-site.mjs`:
   the classic acbpr.com banner (same twelve buttons) rebuilt in HTML/CSS, plus pages for
   inscripción, itinerarios, posiciones, cuartos, todos vs todos, secciones, canchas
   (77-court directory), campeones, resoluciones, contactos (`/directiva`), documentos, reglamento,
   fotos and contacto.

It is separate from the scoreboard app in the repository root and never touches the
scoreboard's `x_club` / `x_team` / `x_player` models.

## Local development

```bash
npm install
cp ../../.env .env            # ODOO_URL, ODOO_DB, ODOO_API_KEY (never commit it)
npm run dev:api               # API on :8787, login codes printed to the console, no emails
npm run dev                   # Vite on :5180, proxies /api to :8787
npm test
```

## Deploy the portal on Render

Create a **new** Web Service from this repository (do not reuse the scoreboard service):

| Setting | Value |
| --- | --- |
| Root directory | `acb-portal` |
| Runtime | Node |
| Build command | `npm ci --include=dev && npm run build` |
| Start command | `node server.mjs` |
| Health check path | `/api/health` |

Environment variables (set them in the Render dashboard):

| Variable | |
| --- | --- |
| `ODOO_URL` | `https://pbopr.odoo.com/` |
| `ODOO_DB` | `pbopr` |
| `ODOO_API_KEY` | API key of the Odoo user the portal acts as |
| `SESSION_SECRET` | long random string (recommended) |
| `PUBLIC_URL` | the portal's public URL, used in emails |
| `ACB_NOTIFY_EMAIL` | optional: gets every new club request and a copy of every team submission |
| `MAIL_FROM` | optional, default `ACB Inscripciones <info@pbopr.com>` |
| `LOGIN_CODE_REQUIRED` | `1` to require the emailed 6-digit code at sign-in. Unset for now (the codes were not arriving): the club's access email alone opens its portal |

Never set `DEV_LOGIN_CODES` in production. Emails (login codes, submission receipts) are
sent through Odoo's outgoing mail server.

## Build / update the Odoo website

```bash
PORTAL_URL=https://<portal-url> npm run website:odoo           # publish to website #2
node odoo-website/build-site.mjs --preview                     # local preview in .preview/site
```

The script is idempotent: it uploads the logo, flyer, stylesheet and the 2027 Word forms
(`ACB_DOCS_DIR`, default `../../Documents `) as public attachments, rewrites one QWeb view
per page, hides Odoo's default header/footer on those pages and points website #2's menu at
them. **Re-running it overwrites edits made to these pages in Odoo's website editor**, so
change the content in `odoo-website/content.mjs` (or `shared/tournament.js` for dates and
fees) and re-run.

### Shareable copy (until website #2 has a domain)

Website #2 has no domain yet, so Odoo only shows it to signed-in users. A static copy of
the same pages is the public link to share meanwhile: **https://acbpr.pages.dev**
(Cloudflare Pages project `acbpr`, account jabesodelacruz@gmail.com).

```bash
npm run website:export                          # writes dist-site/ (no Odoo calls)
node scripts/serve-static.mjs dist-site 5190    # look at it on http://localhost:5190
npm run website:share                           # export + upload to acbpr.pages.dev
```

It does not update on its own: after changing `content.mjs` (and publishing to Odoo), run
`npm run website:share` too. Wrangler must be logged in to that Cloudflare account
(`npx wrangler login`). Internal links point at folders (`/canchas/`) because Pages
redirects `/canchas` there. The Word forms link to their public Odoo attachments, listed in
`odoo-website/data/odoo-docs.json`; publishing to Odoo rewrites that file, so commit it
after a publish that changed a form. The copy is marked `noindex`. Once website #2 has its
own domain, delete the Pages project.

The 2026 archive (PDFs on the current acbpr.com server) is linked through
`ACB_ARCHIVE_URL` (default `https://www.acbpr.com`). Before pointing the acbpr.com domain at
Odoo, move those files somewhere permanent and set `ACB_ARCHIVE_URL` accordingly, or the
archive links will break.

## Admin workflow in Odoo

**ACB Inscripciones → Clubes** shows every club with a *Revisión ACB* badge. Clubs requested
from the portal arrive as **Solicitud nueva** (filter *Solicitudes nuevas*; `ACB_NOTIFY_EMAIL`
also gets an email for each request). Check the data and set it to **Verificado por la ACB**;
the club sees the change on `/mi-club` and in its portal. To hide a club from the public list
and block its access, set its *Estado* to **Bloqueado**.

**ACB Inscripciones → Equipos** lists every team with its state and completion.
Set a submitted team to **Requiere cambios** and write the reason in *Comentarios de ACB al club*:
the club sees it in the portal and can edit and resubmit. **Aprobado** locks the team.

To remove a club, delete its teams first (Equipos list), then the club. Deleting a club
directly cascades in the database and leaves the uploaded files of its teams and players
behind as orphaned attachments.

## Re-running the Odoo model setup

`npm run setup:odoo` creates or updates the models, fields, access rights, admin views and
menu. It is safe to re-run after changing `shared/schema.js`.
